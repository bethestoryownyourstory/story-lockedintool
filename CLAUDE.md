# STORY - working rules

- **The app is LOCKEDINTOOL (owner): STORY is now its own, separate company, so the word "Story" is never shown anywhere in the app** - every text the user can see (screens, toasts, notifications, the setup screen, the app's name under its icon, widget names, folders Documents/Lockedintool and Pictures/Lockedintool, the web icons) says Lockedintool. **The logo is the owner's PERMANENT Lockedintool logo (owner, Oct 2026: "our permanent logo forever") - never the old STORY logo or the earlier tape logo**: ic_launcher.png (1024px, a centred square crop of the owner's picture on its own black background, copied to res/drawable-nodpi by android.yml; also the widget preview) and icon-192.png / icon-512.png (web) are made from it. Internal names stay as they are (StoryNative, story-* storage keys, com.story.launcher, file / class names, server URLs, workflow names) - users never see them. The Dashboard title is two lines, "Locked" over an indented "intool", in EXACTLY the box the old one-word title took (61.17 x 26px on phones, 52 x 22px wide; .story-title / .story-title-l) - same size and the same space around it (owner). The Subscription keeps the owner's plan name "LOCKED IN TOOL" and plan texts. Community's "Stories" feed keeps its name (a feature, not the brand) unless the owner says otherwise. Widget content descriptions read "Lockedintool <page> widget #<id>" (the accessibility regex also still accepts the old "STORY ..." until each widget refreshes).

- **STORY works as one with the phone.** Once on, it is on and always running, like part of the system, and it uses the phone's full potential: STORY does things itself (e.g. silencing apps under the Pages) instead of depending on other apps to cooperate.
- **Black means real black (#000000).** Whenever the owner says "black", use pure #000 -- never a dark grey. The Pages background and cards are #000 (html.focus).
- **No scrollbar lines anywhere in STORY** (no grey/white line down the side of a page). The only exception is the Payments scroll indicator the owner asked for.
- **Pages never zoom in/out on their own.** A page's fitted size is worked out once per screen size (FIT_CACHE) and kept; live changes (prices, profit/loss flips, rows appearing) must not rescale it. Keep layouts the same height in every state (e.g. hidden placeholders).
- **Cool phone (owner): STORY never works when nothing needs it.** Nothing runs on a loop while idle - no endless requestAnimationFrame / redraw loops in any window (the old tilt loop only runs while something moves it; checked: 0 frames in 3s idle in every window). Hidden Pages / Profile (+ gap) windows rest (WebView.onPause in setShown, onResume when shown; never during a call); TradingView rests when not on screen (TvView onPause / onResume); repeating page timers skip while hidden (document.visibilityState). The Always On Display listens for the unlock (Android 13+ KeyguardLockedStateListener) instead of checking 5x a second, and the lock-screen scans (PIN page / quick settings) skip while the AOD is up. New features must follow this.
- **Finish everything, perfectly, before saying it is done.** Every change is complete across every page and state it touches, checked (rendered and tested on all affected pages, Station 3 included), and pushed with a green build. No half-done work, no leftovers for later.
- **The phone's own panel always works on the Pages (owner's call).** The Pages sit in the normal overlay layer under the phone's status bar (clock/battery strip stays visible); never move them above it again, or the notification panel and keyboard break.
- **One thing everywhere.** Anything STORY shows both on the Pages and over apps (Station 3, the dial pad, the message bubble...) is ONE thing: same look, same behaviour, one implementation. Only split it into two when the owner explicitly says so.
- **Unbuilt buttons say so.** Anything not built yet shows STORY's message bubble "... — coming soon" when tapped (COMING_SOON in index.html / showToast). In the app the bubble is drawn natively (StoryNative.toast -> OverlayService.showToast), identical on the Pages, Station 3 and over apps.
